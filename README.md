# 友カフェちゃんBOT
![Icon](https://i.imgur.com/Sq5nZnS.jpeg)

## 概要
友カフェちゃんBOTはディスコードサーバー『"友"カフェ』のマスコット 兼 BOT店員さんです。

## 機能一覧
・カフェの雰囲気にマッチしたチャットコマンド

・コーヒー豆をベースにした通貨システム

・高度なアイテムシステム（ショップ機能など）

・**自動登録システム** - サーバーに参加すると自動的にウェルカムコーヒーと10豆がプレゼントされます！

・**カフェモンスター戦闘（フェーズ3）** - 通常の3ボタンに加え、敵の予兆に対応する一時的な特殊リアクションを持つカジュアルなターン制戦闘を提供します。

## インストール方法
※現在友カフェちゃんは他サーバーでは使用できません。ご了承ください。

## 使用ツール
友カフェちゃんは主にJavaScriptで開発しています。
データベースはMongoDBを使用し、Discord.jsでAPI接続しています。

## 開発環境と本番環境
- ローカル開発は `.env.development` を優先して読み込みます。既存の `.env.dev` もそのまま使用できます。
- 本番環境は Heroku Config Vars を前提にし、`APP_ENV=production` で起動します。
- ローカルで開発用 Bot と Web 管理画面を起動する場合は `npm run dev` を使います。
- Heroku の dev アプリは `develop` ブランチ、本番アプリは `main` ブランチからデプロイする構成にしてください。
- Slash command 登録は既定で `GUILD_ID` 向けです。dev bot がまだそのサーバーに入っていない場合は `REGISTER_COMMANDS=false` にすると起動だけ先に確認できます。
- ローカル環境で `mongodb+srv://` が `querySrv` で失敗する場合は、Atlas の Standard connection string を `MONGO_DIRECT_URI` に設定すると SRV DNS を回避できます。

### カフェモンスター（フェーズ3）

- モンスター設定は [src/data/monsters.json](src/data/monsters.json) にあり、通常14体とボス6体を管理します。通常モンスターは将来用ギミックを1つ、ボスは3つ設定しています。
- `npm run monsters:seed:dev` は接続先URIが指す `dev` データベースの `monsters` コレクションへ、`npm run monsters:seed:prod` は `main` データベースの同コレクションへupsertします。接続先DB名はそれぞれの環境変数で必ず確認してください。
- `npm run battle-items:seed:dev` / `npm run battle-items:seed:prod` は、戦闘用のアイテムマスターを `item_master` にupsertします。ウェルカムコーヒーはHPを8回復し、温かいミルク・角砂糖・とろとろシロップは対応するモンスターへのおすすめアイテムです。
- `！戦闘`（`!battle`）は既存の管理者コマンドです。戦闘カードはチャンネルに表示されますが、操作ボタンは開始本人以外にはephemeralで拒否されます。メッセージ型コマンドはDiscord仕様上ephemeralにできません。
- 通常画面は「こうげき」「アイテム」「しらべる」の3ボタンです。アイテム画面では「回復する」「おすすめを使う」「戻る」だけを表示します。アイテム使用後は敵が生存していれば反撃します。
- 「しらべる」は1戦につき1回です。説明・弱点／有効アイテム・特殊行動のヒントを表示し、次のこうげきのダメージを3増やします。
- 特殊リアクション発生時は通常ボタンを一時的に置き換えます。強攻撃予告型は「よける／ガード／攻め続ける」、弱点露出型は「弱点を狙う／安全に攻撃」、妨害可能型は「妨害する／攻撃を続ける」です。選択後は通常画面へ戻ります。
- 通常モンスターは低確率または1戦1回、強めのモンスターは1戦1回、ボスは設定済みのターンに最大3回まで発生します。全パターンは共通ロジックで実装し、モンスター設定の `mechanics` を再利用します。
- 「こうげき」はプレイヤー攻撃→生存時の敵反撃→HP更新の順に処理します。エスプレッソ・スライムは初期ステータスで4クリック、勝利時に3豆です。勝敗後は5分の再挑戦待機があります。
- 戦闘状態は `battles` コレクションに保存され、起動時および5分ごとの掃除でタイムアウトします。全ボタン操作は原子的なロックで連打を防ぎ、勝利報酬は戦闘IDにより二重付与されません。

## 推奨ブランチ運用
- `main`: 本番デプロイ専用
- `develop`: 開発統合用。dev Heroku アプリのデプロイ元
- `feature/*`: 個別作業ブランチ。`develop` にマージ
- `hotfix/*`: 本番緊急修正。`main` と `develop` の両方に反映
